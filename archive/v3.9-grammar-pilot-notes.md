- `parse.parse_references()` parses `_references.md` into `Reference` records.
- `parse.find_inline_handles()` extracts every `[Handle]` reference-style token from a text body, skipping headings, fenced code, inline code, and inline links.
- `audit.check_reference_handles_resolve()` enforces handle resolution. In Phase 0 the catalogue is deliberately incomplete, so unresolved handles are ERRORs only inside the pilot files; elsewhere they're INFO. From Phase 2 they become ERROR everywhere.
- `build_site.rewrite_reference_handles()` converts `[Handle]` tokens to inline links pointing at `references.md#<slug>`. Code-fence aware; inline-code aware; skip-list for the catalogue page itself.

## How a handle resolves end-to-end

A pilot-file `[NHSE-AVT-Registry]` token resolves like this:

1. `audit.py` reads `_references.md`, sees `### NHSE-AVT-Registry`, registers the handle.
2. `audit.check_reference_handles_resolve()` confirms the token in the metric file matches a catalogue handle. ERROR if not.
3. `build_site.rewrite_reference_handles()` rewrites `[NHSE-AVT-Registry]` → `[NHSE-AVT-Registry](../../references/#nhse-avt-registry)` on the rendered group page.
4. MkDocs slugifies the catalogue h3 to `nhse-avt-registry` automatically (lowercase + hyphenation), so the link target exists.
5. Reader clicks → arrives at the catalogue entry, sees the live URL + (eventual Wayback snapshot) + retrieval date.

## Things to settle before Phase 1

These are the open questions named in `plan-v3.9.md`. The pilot does not commit to any of them; raised here for the gate review.

### 1. Vague-literature rows — discipline-representative or marker?

The pilot scope has zero vague-literature Source rows (`"standard ASR literature"`, etc.) — those start in Phase 2 when we sweep `part-a/asr-transcription.md` and similar. The user's pre-pilot direction was **curated representative citation per discipline** (one ASR survey, one calibration survey, etc.). The pilot doesn't surface any reason to revisit that decision yet.

### 2. Catalogue-entry shape — proposal vs alternatives

The pilot uses h3-keyed-by-handle + bullet-list-of-fields:

```markdown
### NHSE-AVT-Registry

- **Title:** NHS England AVT Self-Certified Supplier Registry
- **Publisher:** NHS England (Transformation Directorate)
- **Source-Type:** framework
- **URL:** https://digital.nhs.uk/services/ambient-scribing/...
- **Archive:** _(Phase 1 — pending snapshot.py)_
- **Retrieved:** 2026-04-26
- **Local-Mirror:** _(reserved for option (c); empty in v3.9)_
- **Cited-by:** _(auto-generated)_

The NHS England self-certification list ... [free-form description].
```

Alternatives the gate could pick:
- **Definition lists** (`Title : NHS England AVT…`) — terser but parses awkwardly with the existing markdown extension set; `def_list` is enabled but the bullet form renders more consistently across mkdocs themes.
- **Front-matter blocks** (YAML frontmatter per entry) — cleanest for parsing but uglier for human reading on the rendered page.
- **Single-line entries** (handle + URL only) — minimal, but doesn't accommodate the future `Local-Mirror` field cleanly when option (c) lands.

Recommend: keep current shape. Reads well rendered, parses cleanly, has named slots for every field including Phase 1 (`Archive`) and option (c) (`Local-Mirror`).

### 3. Handle naming convention — case + format

The pilot mixes:
- ALL-UPPERCASE codes (`DCB0129`, `DSPT`, `DTAC`)
- Hyphenated mixed-case (`NHSE-AVT-Registry`, `IASME-Cyber-Essentials-Plus`, `MHRA-SaMD`)
- Hyphenated lowercase identifiers (none in pilot, but `arxiv-2024-12345` is a likely Phase 1 form for paper handles)

The driver is "what's the most natural reading form for the authority". `DCB0129` is universally written that way; `NHSE-AVT-Registry` reads better as Title Case than `NHSE-AVT-REGISTRY`. The slug at render time is uniform (lowercase-hyphen) so internal mechanics don't care.

Recommend: continue case-by-case, preferring "natural reading form". Phase 1 will introduce more handles; if a pattern emerges (e.g. all paper handles use `Author-Year-arxiv-id`) it can be codified then.

### 4. Cited-by back-reference — auto-generation timing

The pilot does NOT yet auto-generate the `Cited-by:` line. The plan calls for this to be a parse.py-driven render-time field populated on every build. Phase 5 of v3.9 implements this.

For Phase 0 the field exists in catalogue entries as `_(auto-generated)_` placeholder so the grammar is in shape. Recommend: implement Cited-by alongside Phase 1 catalogue construction so we can spot-check on a meaningful catalogue (Phase 1 = ~38 entries, more interesting test surface than 12).

### 5. Source-Type taxonomy — six values currently

Used in the pilot:
- `framework` — multi-section regulatory/governance frameworks
- `regulator-guidance` — operational guidance from a regulator (gov.uk SI, NCSC, ICO, MHRA)

Reserved for Phase 1+:
- `paper` — peer-reviewed publication or pre-print
- `disclosure` — vendor or third-party security disclosure (Mindgard, MIT Jameel)
- `discipline-representative` — one canonical reference per discipline (settles vague-literature)
- `internal-derivation` — analyses cited by ID for traceability (INSYTE, OxonFair extensions)

Recommend: keep these six. Phase 1 will exercise the remaining four; if a seventh emerges it can be added to the catalogue grammar's allowed values.

## Risks and limitations surfaced

1. **`mkdocs --strict` doesn't catch literal `[Handle]` tokens that fail to rewrite.** If the build_site rewriter has a bug, an unresolved handle renders as a link to the catalogue page anchor that doesn't exist, but mkdocs strict mode doesn't flag cross-page anchor failures. The audit's `check_reference_handles_resolve` is the single line of defence. Acceptable for Phase 0; consider adding an HTTP-level link-check pass in Phase 5.

2. **Handle false positives.** The `[Handle]` regex is intentionally lax (any `[A-Za-z][A-Za-z0-9_-]*` not followed by `(`, `:`, or `[`). If a metric ever uses a literal `[X]` for some other reason — citation-style enumerations, pseudo-code in prose — it would either match a catalogue handle (rewritten to a link, surprising reader) or not match (flagged by audit, which is fine because it'd be ERROR-not-INFO if in pilot scope). Surfaced 0 false positives in the actual current text.

3. **Wayback Save-Page-Now not yet wired.** All `Archive:` fields read `_(Phase 1 — pending snapshot.py)_`. The pilot doesn't exercise the snapshot tool; that's a Phase 1 deliverable.

4. **Reader confusion: catalogue page on every click.** The grammar means every reference click goes to the catalogue page, not directly to the source URL. For a reader who only wants the source, that's an extra click. Mitigation: catalogue entries lead with Title + URL, so the "click through to source" path is short. Could be revisited if reader feedback says it's friction.
