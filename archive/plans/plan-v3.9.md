# v3.9 plan — references validity sweep (option (b), forward-compatible with (c))

**Goal.** Every external citation in the taxonomy resolves to (1) a live URL and (2) a Wayback Machine snapshot, recorded in a structured way that an audit check can validate. The grammar and storage layout are designed so a later v3.x can drop in full local mirrors (option (c)) without rewriting any existing citation.

**Non-goals.** No new metrics. No tightening. No roadmap promotions. The big roadmap review remains queued behind this.

**Why now.** The taxonomy makes 221 cited claims (Source rows) and ~37 Reference-Standard blocks naming authoritative documents (DCB0129, NHSE IG guidance, MHRA SaMD, OxonFair, etc.) — none of them currently link out. NHS-domain URLs in particular reorganise frequently; without snapshots the citations silently rot. This sweep makes the taxonomy independently auditable and link-rot-resistant.

The 33 vague-literature rows are the main grammar question: the choice is "force a representative citation" vs "explicitly admit no single source exists". The plan picks the latter — explicit honesty beats a fig-leaf citation.

## Citation grammar (the deliverable that locks everything else)

### Two-part grammar

Every citation has two layers:

1. **Inline reference** — what appears in the metric file. A short stable handle plus a URL.
2. **Catalogue entry** — what appears in `_references.md` (new file). Full bibliographic record + URL + archive URL + retrieval date + (later, in option c) local-mirror path.

This separation is what makes (c) drop-in: the catalogue grows a `Local-Mirror:` field; metric files do not change.

### Inline form (in metric files)

Source rows become:

```
| **Source** | [DCB0129] · [Mindgard 2026 disclosure] · discipline-norm: ASR literature |
```

Where `[DCB0129]` and `[Mindgard 2026 disclosure]` are markdown reference-style links resolving to entries in `_references.md`. The `discipline-norm:` prefix is the explicit marker for vague-literature rows — no link, but no fake citation either.

Reference Standard / Threshold Guidance blocks keep their narrative prose but every named document becomes a `[Handle]` link, e.g. "the [DCB0129] safety case schema" not "the DCB0129 safety case schema".

### Catalogue entry (in `_references.md`)

```markdown
### DCB0129
- **Title:** Clinical Risk Management: its Application in the Manufacture of Health IT Systems
- **Publisher:** NHS England (formerly NHS Digital)
- **Type:** information-standard
- **Source-Type:** framework  (one of: framework | regulator-guidance | paper | disclosure | discipline-norm | internal-derivation)
- **URL:** https://digital.nhs.uk/data-and-information/information-standards/information-standards-and-data-collections-including-extractions/publications-and-notifications/standards-and-collections/dcb0129-clinical-risk-management-its-application-in-the-manufacture-of-health-it-systems
- **Archive:** https://web.archive.org/web/2026*/digital.nhs.uk/...  (specific snapshot URL)
- **Retrieved:** 2026-04-27
- **Local-Mirror:** _(reserved for option (c); empty in v3.9)_
- **Cited-by:** GV.CR-1, GV.CR-4, GV.PD-2, … (auto-generated by build)
```

The `Local-Mirror:` row is present-but-empty in v3.9. When option (c) runs, that field gets populated with `archive/sources/<handle>.pdf` (or similar). Nothing else changes.

### Handles

Stable, human-readable, ASCII, kebab-case-or-title-case. Examples:

- `DCB0129`, `DCB0160`, `DSPT`, `DTAC`, `MHRA-SaMD`, `NICE-ESF`
- `NHSE-IG-AVT-2026-03`, `NHS-LLM-Framework-2025`, `NHS-TEST-2026`, `NHSE-AVT-Registry`
- `Mindgard-Heidi-2026`, `Mindgard-Doctronic-2026`, `MIT-Jameel-2026`
- `OxonFair-2024`, `INSYTE-2025`, `SCRIBE-Wang-2025`, `PDSQI-9`
- `ROUGE-Lin-2004`, `BERTScore-Zhang-2020`

Handles are picked once and never renamed (the audit will enforce this).

## Phasing

### Phase 0 — Grammar pilot (1 commit)

Apply the new grammar to a small, well-bounded slice so we can react before sweeping everything. Pilot covers:

- The 3 v3.8-introduced metrics (GV.SC-12, GV.VT-13, GV.VT-14) — these touch the registry and Cyber Essentials, so they exercise the framework + regulator-guidance path.
- The NHSE AVT Registry section in `_standards-mapping.md` — exercises the standards-mapping treatment.
- GV.CR-4 — exercises a tightened Tier 1 metric with Reference Standard + Threshold Guidance + Source row.

Deliverables in this phase:

- New file `taxonomy/_references.md` with ~10–15 catalogue entries covering everything cited by the pilot scope
- The three metric files updated to the new grammar
- `parse.py` extended to read `_references.md` and resolve `[Handle]` links
- `audit.py` gains `check_reference_handles_resolve` (every `[Handle]` in metric files exists in `_references.md`)
- Pilot commit ends with a short writeup `archive/v3.9-grammar-pilot-notes.md` for fresh-eyes review

**Gate:** stop and review with user before sweeping.

### Phase 1 — Catalogue construction (1–2 commits)

Build the full `_references.md` catalogue covering all ~38 distinct authorities + the paper-citation tail. For each entry: live URL, Wayback snapshot URL, retrieval date.

Tooling:

- A small helper script `taxonomy/tools/snapshot.py` that given a URL hits the Wayback Save Page Now API, waits for confirmation, and emits the snapshot URL. Caches results so re-runs are idempotent.
- The script runs against the catalogue, not against the taxonomy text — single source of truth.

This phase does not touch metric files yet. Output is a complete catalogue.

**Gate:** review catalogue completeness before sweeping metrics.

### Phase 2 — Sweep Source rows (3–4 commits, batched by part)

Convert all 221 `**Source**` rows to the new grammar. Batched by Part:

- Part A (technical pipeline) — 1 commit
- Parts B + C + D — 1 commit
- Part E — 1 commit (largest, governance-heavy)
- Part F + cross-cutting `_*.md` files — 1 commit

For the 33 vague-literature rows: explicitly mark as `discipline-norm:` per grammar; do not invent citations.

For paper-cited rows: link to DOI where available, else arXiv, else publisher landing page.

`audit.py` gains `check_source_row_grammar` — every Source row matches the new shape.

### Phase 3 — Sweep Reference Standard / Threshold Guidance blocks (1–2 commits)

Inline-link every named authority in the ~37 Reference Standard and ~31 Threshold Guidance blocks. Mechanical pass; the catalogue is already built so this is just substituting `DCB0129` → `[DCB0129]`.

### Phase 4 — Cross-cutting + standards-mapping (1 commit)

- `_standards-mapping.md`: every framework section gets publisher URL + archive URL row, in a consistent format.
- `_outcomes-boundary.md`, `_calibration-and-context.md`, `_how-to-use.md`: link any external references they make.
- `README.md`: add a paragraph documenting the citation grammar and pointing to `_references.md`.

### Phase 5 — Audit + build integration (1 commit)

- `build.py`: when assembling the monolith, append `_references.md` near the end (after Part F, before any meta sections).
- `build_site.py`: render `_references.md` as its own MkDocs page; add cross-cuts panel showing reference usage.
- `audit.py`: enable `check_archive_present` (every catalogue entry has both URL and Archive fields populated); enable `check_retrieved_date_format` (ISO date).
- `parse.py`: cited-by back-references — given `_references.md` is the catalogue, parse.py emits which metrics cite which references, populating the `Cited-by:` field on render.

### Phase 6 — Release wrap (1 commit + merge)

- CHANGELOG v3.9 entry
- README + docs/index version bumps
- Header update
- Plan archived to `archive/plan-v3.9.md`
- Tag `v3.9`, merge `--no-ff`, push, delete branch

## Forward-compatibility with option (c)

The grammar reserves `Local-Mirror:` from day one. When option (c) runs in some later release, the work is:

1. For each catalogue entry, download the canonical document to `archive/sources/<handle>.<ext>` (PDF where available; HTML snapshot otherwise).
2. Set `Local-Mirror: archive/sources/<handle>.pdf` on the catalogue entry.
3. Add `audit.py: check_local_mirror_exists` validating every populated `Local-Mirror:` resolves to a real file.
4. Optionally — and this is where (c) gets ambitious — a `check_claim_appears_in_mirror` audit that greps the local mirror for a phrase from the citing metric. This is a stretch goal, not a v3.9 commitment.

**No metric files change** in the (c) upgrade. That's the whole point of catalogue-as-single-source.

Storage: PDFs run 0.5–5 MB each; ~38 documents → ~50–100 MB. Tolerable for the repo. If it grows past that, switch to git-lfs at the (c) upgrade boundary, not now.

## What could go wrong

- **Wayback Save-Page-Now rate limits.** Phase 1 tool needs throttling + retry; build it to be re-runnable so partial progress is recoverable.
- **NHS-domain URLs that won't snapshot.** Some auth-walled or JS-rendered NHS pages refuse Wayback. Fallback: archive.today; failing that, mark `Archive-Status: unavailable` in the catalogue with a reason field, and flag for manual handling at the option (c) stage where local mirror sidesteps the issue.
- **Vague-literature pushback.** If on review the `discipline-norm:` marker reads as a cop-out, the alternative is a curated representative citation per discipline (one ASR-survey, one calibration-survey, etc.) — call this at the Phase 0 gate, not in advance.
- **Handle bikeshedding.** Phase 0 pilot commits to handles for ~10–15 entries; later phases reuse. Don't churn the handles after the pilot gate.
- **Citation rot during the sweep itself.** Wayback timestamps are taken at retrieval; record retrieval date on every entry so a reader can see "this URL was alive on this date" even if it dies later.
