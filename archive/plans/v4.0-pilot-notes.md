# v4.0 Phase 0 pilot notes

**Date:** 2026-05-02. **Branch:** `v4-0-cluster-rename`.

Phase 0 piloted the cluster-code rename on **TP only** (current Part A) plus the companion **"EPR Write-back" → "Downstream Write-back"** rename. The other five clusters (PI / HL / IO / GV / ES) are deliberately left in mixed state for the gate.

## What landed

### Folder + file renames

- `git mv taxonomy/part-a/ taxonomy/tp/`
- `git mv taxonomy/tp/epr-write-back.md taxonomy/tp/downstream-write-back.md`

### Python code

- `parse.GROUP_FILES`: TP entries' keys updated `part-a/<file>.md` → `tp/<file>.md`; the inner `part` field changed from `"A"` to `"TP"` for TP rows. Other clusters still carry letter values (`"B"`/`"C"`/`"D"`/`"E"`/`"F"`).
- `parse.PART_NAMES` renamed to `parse.CLUSTER_NAMES`. New keys: `TP`/`PI`/`HL`/`IO`/`GV`/`ES`. Legacy letter keys (`B`/`C`/`D`/`E`/`F`) kept during the migration so non-TP clusters' `Metric.part_name` lookups still work. **Phase 1 strips legacy letters cluster-by-cluster; Phase 5 drops the alias entirely.**
- New `parse.CLUSTER_ORDER` list — preserves presentation order during the migration without depending on `dict.keys()` semantics.
- `parse.PART_NAMES = CLUSTER_NAMES` alias retained for backwards-compat with anything outside the build that imports the old name. Removed in Phase 5.
- `build.FILES`: TP paths updated; `epr-write-back.md` → `downstream-write-back.md`.
- `build_site.MAPPING` + `SRC_GROUP_FILE_TO_PAGE`: TP paths updated; `downstream-write-back` page rendered at `groups/downstream-write-back.md`.
- `build_site.ANCHOR_REWRITES`: added `downstream-write-back` and kept `epr-write-back` as a legacy alias pointing at the same target page.
- `audit.GROUP_FILES`: TP entries renamed; group label "EPR Write-back" → "Downstream Write-back".

## What worked

- **Inner-key rename deferred to Phase 3.** Keeping `part` as the dimension key during Phase 0 means the JSON/CSV output schema is unchanged; only values shift. This lets the pilot land without breaking the test suite's payload-shape assertions. Phase 3 does the field rename (`part` → `cluster`).
- **Legacy-letter aliases in `CLUSTER_NAMES`.** Without these, `Metric.part_name` for any non-TP metric would have returned an empty string. The aliases make the mixed state graceful.
- **`mkdocs-redirects` for the EPR → Downstream rename.** Plugin install + one config addition; preserves any deep links to `/groups/epr-write-back/` via 301 redirect to `/groups/downstream-write-back/`. Production cost negligible.
- **TP-cluster pilot scope.** Only six metric files touched, plus the cross-cutting prose. Small enough to inspect by eye; large enough to surface the shape issues that will recur across the other five clusters.

## What was awkward

- **`PART_NAMES` → `CLUSTER_NAMES` rename done in Phase 0 even though only TP migrates.** Done because `Metric.part_name` reads from this constant and a half-renamed const is messier than a fully renamed one with backwards-compat keys. Trade-off: the constant looks slightly weird mid-pilot (cluster codes mixed with letter aliases). Phase 1 cleans this up cluster-by-cluster.
- **The `ANCHOR_REWRITES` legacy alias.** Initial instinct was to rewrite `epr-write-back` → `downstream-write-back` everywhere; left the legacy alias in place because some monolith-build references in `_standards-mapping.md` may still use the old anchor (verified: they don't, but the alias costs nothing and de-risks the rename). Reconsider for cleanup at Phase 5.
- **Test `test_references_after_part_f` had to be made forward-compatible mid-pilot.** Renamed to `test_references_after_clusters` and broadened to match both old + new prefixes. This pattern (test-helpers needing to accept both schemes during the migration) will likely repeat in Phase 1 — no other tests currently match against folder paths, so the cost is bounded to this one fixture.

## Recommendations for Phase 1

- **Sweep one cluster per commit.** PI (2 files) + HL (1 file) + IO (2 files) is cluster commit 1. GV (8 files) + ES (1 file) is cluster commit 2. Each commit:
  - `git mv taxonomy/part-X/ taxonomy/<cluster>/`
  - Update `parse.GROUP_FILES` keys + `part:` value
  - Drop the corresponding letter alias from `parse.CLUSTER_NAMES`
  - Update `build.FILES`, `build_site.MAPPING`, `build_site.SRC_GROUP_FILE_TO_PAGE`
  - Update `audit.GROUP_FILES` keys
  - Run `uv run pytest && uv run python taxonomy/audit.py && uv run python taxonomy/build.py && uv run mkdocs build --strict` before committing
- **Defer Phase 4 nav restructure to its own commit.** The TP nav heading was updated in Phase 0 (`A - Technical Pipeline` → `TP - Technical Pipeline`); for Phase 1 the other five clusters' nav headings stay as `B - Pipeline Interactions` / etc. until the dedicated nav-restructure commit. This keeps each Phase 1 commit minimal-scope and the diff easy to review.
- **Phase 2 prose sweep happens AFTER Phase 1 folder renames.** Reason: the prose patterns "Part E" / "the GV cluster" / etc. only need to be settled once the folder-rename behaviour is verified across all six clusters. Don't sweep prose ahead of the rename or we'll sweep again to catch what the rename surfaces.

## Open questions answered for Phase 1

- **Heading shape** (Q2): strip `# Part X` headings; folder name + nav label carries the cluster signal. Confirmed at Phase 0 gate (no source files actually had `# Part X` headings — they were build-time injections).
- **EPR filename** (companion Q1): rename + redirect plugin. Confirmed and shipped in Phase 0.
- **Pipeline Layer enum** (companion Q2): out of scope for v4.0; flag for plan-future.
