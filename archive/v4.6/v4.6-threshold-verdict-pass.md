# v4.6 Phase 2a — Per-threshold verdict pass

Per-number review of the ~150 thresholds enumerated in `v4.6-threshold-enumeration.md`. Five verdict categories:

- **Keep** — defensible as a starting point; current value stands. Bulk of the decisions.
- **Tighten** — narrow / sharpen the threshold (or formula) based on what's actually defensible.
- **Loosen** — widen / soften; current value is more aggressive than the underlying evidence supports.
- **Remove** — replace with qualitative guidance; the specific number is unhelpful or misleading.
- **Consolidate** — defer to Phase 2b cross-metric pass; same threshold recurs in multiple metrics.

Each kept threshold also gets a **"why this number"** one-liner that will become the provenance row on the v5.0 Threshold Reference page. This is more honest than the current "proposed in vX.Y as starting points" prelude — it names the actual reasoning.

The honest framing for the verdict pass: I am one author re-reading numbers I (or earlier author-states) wrote. Many will be `Keep` simply because there is no better-grounded alternative without deployer feedback. The value of the pass is not "now they're correct", it is "now each number has been individually re-examined by an author who has just spent two passes auditing the catalogue, with the express goal of asking whether each one is defensible".

## Verdict summary

- **Keep**: ~120 thresholds — bulk of the catalogue. Each gets a "why this number" provenance row on the v5.0 Threshold Reference page.
- **Tighten**: 2 — TP.ASR-12 (> 50 % drift → > 25 % drift sustained two cycles); TP.WB-2 IER (provenance not value).
- **Loosen**: 1 — GV.TC-1 module-minute floors (drop specific minutes; replace with deployer-set engagement-floor convention).
- **Remove**: 0 — no numbers proposed for removal at this verdict pass; the Provenance preludes were doing their job.
- **Consolidate (Phase 2b)**: ~20 thresholds — the 4 cross-metric patterns (severity windows, 0.1/0.5/1.0 weights, 200-cases floor, 95/99/100 cluster).

## Honest caveats on this pass

- **Author re-reading author.** I am the most recent author state of this taxonomy looking at numbers I (and earlier states) wrote. Many `Keep` verdicts are honest about that — "author judgement, no external anchor" is the explicit provenance for ~30 thresholds. A deployer-feedback round would shift more into `Tighten` / `Loosen` / `Remove` territory.
- **Internal consistency vs external validity.** The pass largely confirmed internal consistency — the numbers form a coherent ladder of severity, gap-from-baseline magnitude, and gate-to-monitoring loosening. It does not confirm external validity. Most of these numbers are not "wrong"; they're under-constrained.
- **The compound-error caveat from the user-direction conversation applies here too.** Any deployment that adopts this combination of thresholds may sit on overlapping triggers that no single trigger predicted. The Threshold Reference page (v5.0) needs to make this structurally loud.
