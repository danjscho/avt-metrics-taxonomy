## Why this exists

User noticed TP.ASR-13 Numeric Accuracy is labelled `Measurement Cadence: One-off gate` but its body explicitly describes **monthly review of production-traffic numeric accuracy**, drift triggers sustained over two months, and pause-on-confirmed-dosage-error in production traffic. Cadence label contradicts body.

**This is not unique to TP.ASR-13.** A scan of all 51 metrics with `Measurement Cadence: One-off gate` found that **21 of 51** also list `Periodic Audit` or `Continuous` in their `Lifecycle Phases` dimension. The Cadence dimension is systematically under-claiming for ~40% of the "one-off" set.

## What v5.0.3 does

Two-phase, in this order:

### Phase (a) — fix TP.ASR-13 specifically

The case the user raised. Single metric edit.

- File: `taxonomy/tp/asr-transcription.md`, line ~678
- Change: `Measurement Cadence | One-off gate` → `Measurement Cadence | Periodic audit`
- Rationale: body has pre-deployment gate + monthly periodic audit + drift trigger + production-traffic pause. The dominant cadence in body is periodic audit; pre-deployment is in `Lifecycle Phases` already.
- Add a `**Change history:**` stanza below the dimensions table:
  > **Change history:** v5.0.3 (Cadence corrected: One-off gate → Periodic audit; the body has always described periodic-audit triggers and a production-traffic pause condition).
- No body content edit beyond the stanza. Trigger Conditions / Operational Specification stay as-is.

### Phase (b) — full cadence audit triage file

`v5.0.3-cadence-audit.md` at repo root. Per-metric verdict for all 51 "One-off gate" metrics:

| Verdict | Meaning |
|---|---|
| **Keep** | Body genuinely is one-off (e.g. pre-deployment-only, never re-measured) |
| **Change** | Body has periodic / continuous triggers; should change Cadence to match |
| **Multi-cadence** | Body genuinely combines pre-deployment gate + periodic audit, but the dimension can't express that today (flag for v5.1+ structural fix) |

Scope: research output only. No metric edits beyond the TP.ASR-13 fix in (a). The triage file proposes the verdicts; v5.1.0 (a future MINOR) applies the bulk of them after review.

### Output structure for the triage file

For each of the 51 metrics:

```
| Ref | Name | Tier | Lifecycle Phases | Verdict | Rationale (≤1 line) |
```

Group by verdict at the top. Headline counts: `Keep: ~30 / Change: ~15 / Multi-cadence: ~5` (rough — actual numbers from the audit).

Include a discussion section:

- **The structural alternative** — replace `Measurement Cadence` (one value) with two fields: `Pre-deployment Gate (yes/no)` + `Ongoing Cadence (Continuous / Periodic / None)`. Bigger change; defer; flag as v5.1+ candidate.
- **What changing the cadence label actually changes downstream:** CSV/JSON `cadence` field, the Cadence column in `_tier-1-quick-reference.md`, the Cadence filter in the explorer, audit checks (none currently constrain cadence).
